Disposable Linux VMs for untrusted workloads

Want to try an unfamiliar repository? Clone it inside a Chasm sandbox, install its dependencies, and run its tests. Each sandbox is a Linux VM on your Debian host, with its own kernel, workspace, and CPU and memory limits. Stop it to pick up tomorrow, or delete it when you’re done.

Install Chasm Compare sandboxing tools

Can I run Chasm on my host?

Start small: run a Linux sandbox with a 4 GiB guest disk on Debian 13. Install the compact configuration.

What does a sandbox isolate?

Each VM has its own kernel, root disk, and /workspace. Host administrators retain access. Every sandbox on the site mounts /shared read-write, and guests on the stock bridge can communicate directly. Chasm is designed for a trusted single operator. Architecture and network boundaries

How do I run my first workload?

On a provisioned host, run these commands as the operator. Work inside the guest shell and type exit to return to the host.

{% highlight bash %} chasm create demo chasm start demo chasm shell demo {% endhighlight %}

Use chasm stop demo to keep the VM and workspace for later. Use chasm delete demo on the stopped sandbox to remove both. Files on /shared survive deletion. First sandbox walkthrough
